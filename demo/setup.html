Setup

Load the shared core once, then only the components you use. Each component page supplies its exact loading snippet and copyable examples.

Classic scripts

Load component CSS, core JavaScript, then component JavaScript. Use defer so the markup is parsed before elements initialize. Avatar is the example here.

<link rel="stylesheet" href="./dist/markup-ui-avatar.css">
<script defer src="./dist/markup-ui-core.global.js"></script>
<script defer src="./dist/markup-ui-avatar.global.js"></script>

Additional components need only their own CSS and JavaScript; do not load core again. Classic exports use MarkupUICore and family globals such as MarkupUIAvatar.

ES modules

The component module imports core automatically. Keep their generated files together when serving modules directly, and load the CSS separately.

<link rel="stylesheet" href="./dist/markup-ui-avatar.css">
<script type="module">
  import { Avatar } from "./dist/markup-ui-avatar.js"
</script>

With a bundler, use the package exports and route the stylesheet through your asset pipeline.

import { Avatar } from "@dataengine/markup-ui/avatar"
import "@dataengine/markup-ui/avatar/style.css"

Browser entries register their family automatically. Use one compatible core version and one module format per application; do not mix ESM, classic or aggregate copies.

Styles and composition

Component styles are required. Themes, document styling, demo code viewers and API tables are separate conveniences, not runtime dependencies. The shared-core components do not require the aggregate library, query helpers or binding services.

When copying an example that uses another component, also load that component's files. Demos may include extra Button, Badge, Switch or Tabs assets for controls and composition.

HTML classes and CSS custom properties are Web styling tools, not cross-platform behavior APIs. Standard examples keep demo layout styles outside the component markup; custom-style examples identify their Web-specific styling. Native targets use their own mappings of the logical component properties and style resources; this implementation currently targets Web.

Use each example's code toggle for its authored markup. Preserve its native controls and required regions. For dynamic content, prepare the complete subtree before connecting it; see the component's behavior section for update and lifecycle rules.

Run this demo locally

pnpm build
pnpm demo

Open the component browser through the local HTTP server (port 4173 by default), rather than opening HTML with file://. API JSON is generated for the demos during the build and is not shipped in the component runtime.
