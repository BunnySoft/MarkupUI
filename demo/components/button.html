Behavior and accessibility

One native owner

Author one direct button or a, or provide phrasing content and Button creates a native button type="button". Content is moved, not cloned. Do not nest interactive controls inside it. The wrapper has no button role or tab stop. control is the read-only Web reference to that native owner (null before connection); it is not portable metadata.

click(), focus(options?) and blur() delegate to that owner. Keyboard activation is browser-owned: Button does not synthesize a second event. Listen for native click (a MouseEvent/PointerEvent), not m:click. Native event propagation and cancellation apply; preventing click's default prevents submission/navigation. There is no custom activation payload.

Tone, appearance and shape

type is semantic tone, appearance is one visual treatment, and shape is one geometry choice. Secondary, tertiary, quaternary, ghost, dashed and text treatments remain available, as do round and circle shapes, borders, strong text, block sizing and CSS color/icon overrides. variant, type="text", and overlapping appearance/shape boolean switches are not aliases. Use appearance="text" instead.

Names and icons

Text normally supplies the accessible name. For an icon-only control, supply label, host aria-label/aria-labelledby, or a name on the native control. label overrides the host's aria-label; native aria-labelledby still follows the browser's naming precedence. Removing overrides restores authored labels.

Mark at most one direct decorative icon data-part="icon" aria-hidden="true" on the native owner or in the wrapper's content; icon-placement changes its visual side, not DOM order. Other data-part/data-state markers are owner-scoped implementation details, not additional component elements. The hidden spinner replaces icon presentation only; loading retains node identity, listeners and the accessible name.

Forms, links and disabled/loading

An authored native button keeps its type (including HTML's default submit) and attributes. Explicit host attr-type and form inputs override the native equivalents; removing them restores authored values. form on Button is an optional form ID, not an HTMLFormElement; use control.form for the native form owner. Forwarded name/value, action, method, encoding, target and no-validation inputs only affect native buttons. Validation and submitter form data remain browser-owned.

For links author <a href="…" target="…" rel="…">. Disabled/loading temporarily remove href, suppress click/auxclick and exclude the control from sequential focus; authored attributes, including live edits, are restored afterward. Native disabled buttons and disabled fieldsets are honored, including the browser's first-legend exception. Disabled/loading focus() does nothing. focusable="false" alone only excludes sequential navigation: programmatic focus remains available.

Presence booleans such as disabled/loading are true whenever present, even if the attribute text is "false"; remove them or assign false. Bordered/focusable use explicit true/false encoding and default to true. Optional form values and group size use null for absence. Invalid property values throw; invalid markup is rejected when read or synchronized rather than silently selecting a fallback.

Group naming uses native aria-label/aria-labelledby. Group size defaults to null (no override); no roving-tabindex or toolbar keyboard model is introduced. Loading motion respects reduced-motion settings, and focus indicators support forced colors.
