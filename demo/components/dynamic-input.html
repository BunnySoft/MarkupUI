Behavior and Mapping

The default field needs only core and Dynamic Input. The template example additionally selects Input, Box, Form and Button, with their declared dependencies. These are not dependencies of Dynamic Input itself.

m-dynamic-input-template contains the content of one repeated row. The Web renderer captures it in an inert native template and generates row actions. Load the selected field families before initializing the collection. Do not put IDs, autofocus or initially checked radios in a reusable template; use initializeRow for unique Web ID relationships.

rows exposes stable keys. Use add(index?), move(key, index) and removeRow(key); remove() removes the component itself. Bounds are integers with 0 <= min <= max <= 100 and max at least 1. Initial generated rows are added up to min through the same lifecycle hooks. Subsequent bound changes must contain the current row count and never allocate or truncate.

Structural transactions emit bubbling m:change with {type, row, index, previousIndex, rows}. Field edits and reset retain native events; values are not flattened into comma-separated strings. Disabled prevents native user interaction but does not forbid explicit programmatic transactions. Reset changes current fields to their defaults, not the row set. Cancelled clicks and resets are respected.

initializeRow runs on a detached new row and connectRow runs when a row connects, including reconnect. Both are synchronous Web-only hooks; register resource disposal with context.onCleanup. Surviving rows, controls, listeners, defaults and keys are retained. Native authored container/template/action anatomy remains an explicit Web interoperability path through the same controller, not the portable contract.
