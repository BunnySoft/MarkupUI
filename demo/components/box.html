API

Loading API documentation.

Ownership and lifecycle Label, Footer, Article, Strong, Em, Small, Pre and Details create one stable native owner on Web. They move the original content without cloning it. Late content and reconnect retain node identity and listeners. Names and descriptions on these elements are forwarded to their native owners. Label accepts a public field ID or a native control ID. Wrapping a field also provides native association. Required marks the label; it does not change the field's validation. Native activation owns cancellation and disabled behavior. Details accepts at most one direct Summary and independent nested disclosures. Its open property reads live native state. The Web renderer creates the direct summary required for keyboard activation and hiding closed content. Native toggle notifications emit m:toggle with an open Boolean. Browser keyboard and assistive-technology acceptance remains a release gate.
