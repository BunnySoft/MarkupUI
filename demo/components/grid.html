Behavior, composition and styling

Grid/GridItem are passive ViewElements. Mixed text, comments, late children, listeners and nested layouts remain authored nodes. No observers, clones, child filtering, keyboard engine or custom events are installed.

Grid uses two-dimensional tracks and justify-items; Flex uses one-dimensional flex sizing and justify-content. FormItemGi remains Form's separate two-column field layout with its existing narrow/full-width rules; it does not depend on Grid.

Grid and GridItem may compose passive Collapse headers, Dropdown labels/triggers and Tooltip content only when every descendant still satisfies that owner's restrictions. Interactive descendants, arbitrary widgets and shadow content remain rejected there.

External native CSS declarations override the low-specificity layout defaults. Public --m-grid-* style tokens remain available when the corresponding typed setting is absent; removing a setting restores that style resource. CSS-wide columns keywords (inherit, initial, unset, revert, revert-layer) lease the native grid-template-columns declaration so they keep their native reset/inheritance meaning. Private renderer variables and those declarations are reversibly leased; later application writes survive disconnect. Style resources may intentionally differ from configured property values.

The retained .m-grid/.m-grid-item native CSS skin supports existing semantic containers; it is not a second JavaScript API. Select the Grid family explicitly: the aggregate no longer registers legacy MGrid. The preview palette, padding, borders and custom rows are Web styling, not portable component defaults.

Outside the opt-in, native layout and semantics remain unchanged.
