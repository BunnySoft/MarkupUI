Typed options and async queries

Type any text to load suggestions, or “error” to see a rejected query. Changing the value/data, resetting or disconnecting aborts obsolete work.

Query now No query yet. 
const field = document.querySelector("#async-auto-complete")
field.options = Object.freeze([
  Object.freeze({ value: "Paris", label: "France" }),
  Object.freeze({ value: "Tokyo", label: "Japan" })
])
field.load = async (query, { input, signal }) => {
  const response = await fetch(`/places?q=${encodeURIComponent(query)}`, { signal })
  if (!response.ok) throw new Error("Suggestions could not be loaded")
  return response.json() // validated unique value/label/disabled data
}
await field.query() // rejects on loader/data failure; no value write or synthetic selection
field.value = "Unlisted" // silent live write, not a reset default
field.defaultValue = "Tokyo" // native dirty-value/reset rules
field.refresh() // restore configured suggestions and cancel pending work

Value, events and native ownership

  • value always reads the actual native string, including silent native edits and free text; empty is "", never null. Property writes are silent and do not mirror the value attribute. That attribute and defaultValue configure the native reset default, without overwriting an already dirty value.
  • The browser owns filtering, the datalist popup, keyboard/Enter, selection, focus, validation, name/form association and submission. Suggestions are not an enumeration constraint. Disabled suggestions can still be typed as free text. Native input/change remain unchanged.
  • m:change { value } is emitted once on native commit or an available clear() action, including clearing an already empty field. Clear focuses the native input but does not synthesize native input/change. All m:* notifications bubble, are noncancelable and are not composed.
  • The existing m:select { value } notification now belongs to the shared owner in both entries. It means an available, noncomposing native input value matches a currently enabled suggestion, including text typed manually; it is not proof of choosing from the popup. Empty, disabled and composing matches do not notify. Browsers expose no source-specific datalist selection event, and neither entry invents a selection origin.
  • Only the shared owner runs debounce, IME coordination, availability checks, AbortSignal, generation/freshness checks and reset cleanup. query() returns an immutable updated/skipped/aborted result with a live current flag; unexpected failures reject and emit m:auto-complete-error, including unexpected late rejections. Expected abort is not an error. Successful queries emit m:auto-complete-results without changing value.
  • maxResults bounds explicit transient setSuggestions() and loader results (oversized results reject, not truncate). Static configured/native options are not capped. Refresh, native reset and disconnect restore baseline options; canceled reset preserves settled data/value.

Data and content regions

Direct m-option children are inert suggestion configuration, not interactive option regions. Their value attribute (or trimmed text fallback), label attribute (or text label) and boolean-presence disabled map onto native datalist options. The original configuration nodes remain hidden while connected, with identity/listeners retained, and their data is available again after reconnect. Late configuration edits are projected by the same owner.

options is property-only immutable data: strings or records with a unique nonempty string value, optional string label and optional boolean disabled (strings up to 2048 characters). Invalid/sparse/duplicate data fails before replacement. The setter copies/freezes records and arrays; assigning it makes that schema authoritative over markup configuration. It never writes value. Surviving projected native options retain identity. setSuggestions() is a temporary result, not a second configured data source.

Ordinary phrasing content is retained. The Web interoperability content region can adopt one actual native input and one associated datalist; directly authored native options are moved, not cloned, and their labels/listeners/template content are retained. Permissive native fallback options (including empty/duplicate values) remain native, independently of the strict portable data schema. Nested AutoComplete families are not consumed by their parent.

An optional Web-only p, span or div[data-auto-complete-status] must be plain, nonlive, nonfocusable text with no element children. Otherwise a plain status is generated. Loading/error/empty text never becomes a selectable pseudo-option. Original status text and renderer-owned attributes are restored on cleanup without erasing later application changes.

Accessibility and Web interoperability

Provide a label for the actual control. Host aria-label, aria-labelledby and aria-describedby are projected onto the stable native input; adopted native labels and descriptions survive. The host is not focusable and no artificial combobox/listbox role, expanded state or active-descendant model is added. Native datalist presentation and assistive-technology support depend on the browser; those broader acceptance checks are not claimed by the unit fixtures.

native, datalist, status, form and native validity methods are explicit Web inspection/interoperability surfaces. Native constraints beyond the typed host settings can be authored on an adopted input or assigned through native. Host mappings are reversible; reconnect retains native identity and live/default values without duplicated callbacks.

The optional createAutoComplete(input, options) entry uses exactly the same owner as the element. Supply one connected text/search/email/url/tel input, an explicit list association and an exclusive connected datalist with a stable unique id. Competing managed writers, changed anatomy or replacement popup ARIA semantics fail/disconnect rather than taking over. Its setOptions(), value, defaultValue, configure(), query/reset lifecycle and notifications are the element's behavior, not a separate native implementation.

The family loads only core, AutoComplete runtime and its CSS. Button/Typography are additional demo selections. Public CSS tokens customize native field paint; Input-owned .m-input fields keep their own paint and sizing. No Input registration, binding package or aggregate bundle is required.
