Behavior, native ownership and Web styling

Input accepts text/password/search/email/tel/url only. Textarea is a separate native kind; changing a supported Input type retains its input node. Converting Input to Textarea is not an API: author a new element and native control, with its own listeners/edit history. Unsupported types and invalid typed values throw, never silently coerce. Native selection methods retain native InvalidStateError behavior for email/url. Browser-specific editing history, autofill and virtual keyboard behavior are not simulated.

The native getter exposes the actual HTMLInputElement or HTMLTextAreaElement (creating one if absent). Supply at most one matching native field; do not add a second after materializing native. Prefix/suffix nodes and listeners are retained. A native control may be supplied before connection, including by the HTML parser. The host has no role, tabindex or form internals. Name every native control with a visible native label or host/native aria-label; labels target the native ID, never the wrapper. Keep action buttons outside labels and other interactive content.

Host value attributes initialize/update the native default (and current value only while the native dirty-value flag permits). The value property updates only the live native value and is silent. defaultValue changes the native reset default; reset updates count after the browser default action, emits no editing events and respects cancellation. Name, placeholder, lengths and rows properties write native properties; their initial values and absence semantics come from native HTML, not library defaults. Host native attributes are forwarded at initialization and on change; absent host attributes leave authored native attributes alone. Direct native value writes require refresh() for decorations.

Supported host native attribute mappings: value, name, placeholder, disabled, readonly, required, minlength, maxlength, form, autocomplete, inputmode and aria-label/labelledby/describedby/invalid; Input also type/pattern, Textarea also rows/cols/wrap. Other native capabilities, including autofocus, spellcheck, inputMode and selectionStart/End/Direction, remain available on native. Native defaults include value/defaultValue/name/placeholder="", disabled/readOnly/required=false, no form when unassociated, lengths=-1 when absent, Input type=text and Textarea rows=2. Authored HTML or browser association determines the actual initial state. Native readonly validity/form getters are computed, not configurable defaults.

Ordinary typing/composition/input/change events bubble from the native owner without duplicates or m:input/m:change aliases. Programmatic value/default/type/selection writes do not synthesize editing events. clear() is a user-intent action: when editable and nonempty it sends synthetic noncancelable input (bubbling/composed), change (bubbling), then m:input-clear with {previous} (bubbling). Button actions run in the next task so a later click listener may cancel with preventDefault(). Clear returns focus from its own button to the native field; neither action submits. Reveal emits no editing events. Composition blocks clear/reveal and host value replacement; ordinary native writes retain native semantics.

Disconnect releases listeners/observers/tasks, conceals passwords and restores still-owned action/count state, not value or author attributes. Disconnected property writes remain native and silent; reconnect reapplies decorations once. Actions queued before reset/disconnect/focus loss cannot reveal a stale password. Disabled includes native fieldset inheritance, not a duplicate host state. Hidden/inert and readonly block actions. Use reportValidity() for native invalid focus and setCustomValidity() for native custom messages; no parallel form engine is installed.

Presentation defaults: size=medium (34px), status=null, borderless/clearable/showCount=false. Input also has round/showPassword=false; Textarea has autosize=false. Presence attributes enable even when text is "false"; remove or assign false to disable. Tiny/small/large are 22/28/40px. Explicit authored data-input-clear/reveal/count nodes also opt into enhancements; boolean properties create/remove only generated decorations and never discard authored ones. formatCount is an optional plain-text function; undefined restores UTF-16 length and native maxlength. Autosize is CSS field-sizing with native resize fallback, not JavaScript measurement.

Theme tokens --m-input-* own exact color, radius, font, padding and responsive sizing; --m-input-min-rows/--m-input-max-rows default to 2/8 for CSS autosize. These are Web styling, not portable numeric properties. The demo uses 2/6. Existing dark/light, RTL, forced-color and print safeguards remain; no animation is introduced. Group/label are passive presentation and preserve native labels/buttons and late content. Input itself is interactive and is not accepted in passive Collapse, Tooltip or menu labels.

The manifest accounts for Input, shared core and required native-control mechanics. The package exports the four classes, registerInput and public types; the old createInput/controller helpers are internal, not public APIs. Unmigrated controls retain their internal native enhancement and CSS skin without importing Input registration.
