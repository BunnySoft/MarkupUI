Behavior and accessibility

Author Upload and its regions using m-* elements. The Web renderer owns the labelled file input, native buttons, list, progress and fieldset. The optional trigger has native keyboard activation; the drop region is not a button. No hidden-field replacement or file metadata cache substitutes for actual files.

Assign options with an explicit transport(file, context). The context provides an abort signal and byte progress reporting; success requires {status: "finished"}. Cancellation does not undo server effects or free a slot until the request settles. Configure only while idle. Reconnecting never automatically resends retained files.

The default selection mode is replace; append and automatic upload are explicit options. File/count/concurrency limits reject whole batches. Accept is a chooser hint, not server-side validation. Without native FileList synchronization the visible chooser remains usable for submission and enhancement controls stay hidden.

The demo additionally selects Button, Typography and Form. These are not Upload runtime dependencies. Files, transport callbacks and the native inspection property are Web interoperability surfaces.

upload.options = {
  concurrency: 2,
  transport: async (file, { signal, reportProgress }) => {
    const result = await applicationUpload(file, signal, reportProgress)
    return { status: "finished", response: result }
  }
}
