Color Picker

Bounded sRGB colors, real HEX/RGB/HSL editing modes and cross-browser alpha controls, coordinated by one native owner.

ColorPicker's own stylesheet themes Apply, Restore draft, Clear and the mode selector, including hover, pressed, disabled, keyboard-focus and forced-colors states; no Button component dependency is needed. The draft field, readout and actions fit narrow columns, wrapping as needed. The RGB chooser, standalone draft input and native mode selector keep a 1px themed focus border without an outer glow or stacked outline; the draft also has a themed caret. Buttons and the alpha slider retain a thin themed keyboard outline. High-contrast mode uses a 2px system focus outline; drafts composed with Input keep Input's own styling and disabled states. Existing --m-color-picker-border, --m-color-picker-radius, --m-color-picker-color, --m-color-picker-background and --m-color-picker-focus tokens customize these controls. The RGB chooser and select popup retain native browser behavior.

Value, syntax and lifecycle contract

value remains a string: "" for empty, lowercase #rrggbb for opaque colors, or rgba(r, g, b, a) for transparency. The initial/default color is black unless authored. Programmatic value writes are silent and preserve dirty drafts; value markup defines the default, not a live mirror. defaultValue updates a clean current value; reset restores the default silently and clears live/draft dirtiness. Cancelled resets retain both.

Accepted syntax is exactly six/eight-digit HEX, comma-separated rgb(r,g,b)/rgba(r,g,b,a), and hsl(h,s%,l%)/hsla(h,s%,l%,a). RGB channels are integers 0-255. HSL hue is 0-360 (optional deg), saturation/lightness 0-100%, and alpha 0-1; decimal channels allow at most three fractional digits. HSL is rounded to eight-bit sRGB. Eight-digit HEX alpha is converted to the nearest thousandth; other numeric alpha is retained exactly. No shorthand, named colors, percentage RGB, slash syntax, variables, wide-gamut CSS, negative values, surrounding whitespace or line breaks. Invalid nonempty values fail before mutation, never clamp to black or drop alpha.

formattedValue is the selected-mode projection, not the form value. HEX shows RGB only; six-digit HEX draft edits preserve the existing/range alpha, while eight-digit HEX supplies explicit alpha. RGB/HSL drafts can include alpha even when the range is hidden. Apply or Enter commits a valid draft; Restore draft replaces it deliberately; Clear commits empty unless interaction is locked. An alpha range change commits after its input draft, with cancellation/newer-work checks. Clean projection commits do not quantize the committed color again.

The existing concrete owner handles all parsing, drafts, notifications, validation, forms, reset and reconnect. configure(record) validates the complete record before any update. Modes/showAlpha update in place without rebuilding state or native controls. Readonly locks editing while retaining form submission; disabled and ancestor fieldsets use native disabling. Authored native nodes, labels, datalists, ARIA, listeners and text selection survive scalar updates. Disconnect releases listeners, observers and queued actions; reconnect reuses the same owner and controls.

Real accepted user changes emit one m:change with the canonical value; deliberate commit/clear also send one native RGB-owner input/change pair, guarded against reentrant supersession. Native RGB input/change are not duplicated. Unsupported native alpha/colorspace anatomy reports m:color-picker-error and withdraws enhancement. No chooser, clipboard or EyeDropper is opened by setup or setters. Validation uses the labelled native draft field, preserving application custom validity. No screen-reader or real-device acceptance is claimed.
