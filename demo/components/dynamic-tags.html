Behavior and ownership

Set draft and call commit() to add a tag. A commit returns added with its tag descriptor, or rejected with a reason. Blank, overlong, invalid, unavailable, composing and stale drafts are retained. Whitespace, case and commas are preserved; the default duplicate policy is allow. Read values for strings and tags for stable keys. removeTag(key) removes one precise key; unknown keys throw. clear() emits one change per removal and stops if cleanup throws. The native remove() still removes the element itself.

max is an integer from 1 to 100, default 20. Reducing it below the current count or enabling duplicate rejection while duplicates exist is invalid. Property changes do not truncate, normalize or recreate rows. m:change bubbles with value, type and tag; rejection and error events do not bubble. Error details distinguish failures before a commit from cleanup failures after removal.

Enter and Add commit; modified/repeated Enter and IME completion do not. Escape cancels a pending commit without clearing the draft. No blur or Backspace removal is implied. Native reset restores the current fields' defaults, not the initial row list, and can be cancelled. Disconnect cancels pending work and disposes row resources; reconnect preserves existing fields and drafts.

The optional Web callback createTag synchronously derives a string for future commits. The Web-only connectTag(row, context) hook attaches resources and registers cleanup with context.onCleanup(). It runs for new rows and again on reconnect. Hooks must not return promises, reenter operations, or replace committed value controls.

Author the complete form with m-form, m-dynamic-tags and m-button. The Web renderer creates the real form, controls and fieldset; application markup does not need their HTML equivalents. Configure name, maxlength and editor-label on m-dynamic-tags. Defaults are tags[], 128 and New tag. Drafts are unnamed and never submitted. Form and Button are additional selections for this example, not Dynamic Tags dependencies.

Web-only interoperability escape hatch

This is not the portable authoring contract. Existing native forms may supply data-dynamic-rows, data-dynamic-template and hidden data-tags-entry regions inside the element. Rows require stable data-dynamic-key values, one named readonly text field marked data-tags-value, and hidden type=button remove actions. Templates have one unkeyed row and no IDs. Native names, labels, listeners and defaults are retained. The editor must remain unnamed, with maxlength 1-2048 managed through the component while connected. Optional data-tags-status is plain, non-live text. Use the exposed native editor for Web validity and focus integration; no proxy hidden fields or interactive chip roles are created.
