Values, defaults and ownership

Count is a positive safe integer, defaulting to 5; there is no artificial ten-choice limit. Whole scores (or half scores with allow-half) must be in range; invalid scores and schema changes that discard a live/default score fail instead of clamping. Live count/half updates retain surviving generated controls. Authored native groups must supply complete ascending choices; change their anatomy before calling configure. Fractional counts are rejected rather than rendering a truncated scale.

Null is no selected radio and submits no value. Zero is a real score: generated m-rate includes and initially selects a labelled zero choice, preserving its initial API value of 0. Authored groups keep their actual checkedness/defaultChecked and never acquire a fabricated zero choice. Setting value/setValue is silent; an initial generated value also establishes its reset default unless default-value is supplied. Later value changes never rewrite defaults. defaultValue is independent; an explicit null is written as value="null" or default-value="null".

A generated fieldset and its visible legend own group semantics. The host has no radiogroup role or tab stop. label names the generated legend; name and the Web form attribute map to native radios. Original native legends, external labels, associations, decorations, controls, ARIA and listeners survive enhancement. Browser radios retain exclusivity, keyboard navigation, validation, focus and FormData; no hidden duplicate score is submitted.

clear() returns whether a selected score was cleared. clearable enables a generated clear control and selected-choice clearing in either entry; authored clear buttons remain available without that option. User radio commits dispatch one asynchronous bubbling m:change with a numeric value, in addition to the existing nonbubbling m:radio-group-change. Clear dispatches nonbubbling m:rate-clear and one bubbling m:change with null, without synthetic input/change. Nonbubbling events are on rate.native (or the authored fieldset); listen there or capture on the host. Programmatic writes, refresh and reset emit neither. Pending clear and radio notifications are canceled on disconnect; reconnect keeps live/default native state and node identity.

Readonly is a Rate policy, not a nonexistent radio readonly attribute. It reversibly disables native choices and excludes their submission, while permitting silent API writes. Disabled ancestors and authored per-control disables remain effective. External peers sharing name, actual form and tree are rejected by native-radio without renaming them. Invalid late anatomy/formatting emits m:rate-error; explicit calls throw. Real screen-reader and device acceptance remain separate from these examples.
