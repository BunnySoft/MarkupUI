Native state, labels and loading

Click the setting label or focus its input and press Space. Accepted activation emits native input then change, once each. Loading cancels activation without disabling submission or moving focus.

Checked submits “enabled”; unchecked submits nothing. Loading is an explicit local flag, not a pending network request or asynchronous checked-update guard.

Behavior, accessibility and dependencies

Switch extends ViewElement and registers only m-switch. It adopts one native checkbox and real native label, generating omitted chrome around surviving text/content. The checkbox alone has role="switch"; the host has neither role nor tab stop. Size defaults to medium, square/loading/disabled/required to false, status to null. Native absence means checked/defaultChecked=false, value="on", defaultValue/name="". Authored defaults, dirty checkedness and actual form ownership take precedence over these absence values.

Host checked, value, name, disabled, required, form and naming/description/invalid ARIA attributes forward to the native owner. The checked attribute sets defaultChecked; direct property writes change native state and are silent, including while loading or disabled. The form property is read-only; the form attribute selects an external form. Native input, change and invalid keep their browser targets and flags. click(), focus(), blur(), checkValidity(), reportValidity() and setCustomValidity() delegate to that same owner.

loading is a presence flag OR authored aria-busy="true". It leases aria-busy/aria-disabled and optional [data-switch-loading] visibility without changing native disabled, checkedness, defaultChecked or form submission. Reset does not clear explicit loading. Same-value author writes survive cleanup. Disconnect removes owned listeners, queued refresh work and leased busy attributes; reconnect restores the requested loading presentation. error and non-bubbling m:switch-error report invalid binary content; correct it and refresh().

There is no mixed Switch state, readonly behavior, checked-update callback, asynchronous guard, promise completion or automatic request cancellation API. Native indeterminate/readonly and host readonly are rejected rather than silently supported. Applications own any asynchronous work and must cancel or ignore stale results after newer writes, reset and disconnect. Completing that work with checked is a silent programmatic write, not a fake user change. Use disabled or loading for the supported activation restrictions.

Keep state/icons and loading decorations direct, aria-hidden and noninteractive; use .m-switch__state with .m-switch__on/.m-switch__off and checked/unchecked icon hooks. These CSS regions preserve authored nodes. The stable setting label must not depend on on/off text. Interactive Switch is not permitted inside passive Tooltip, Collapse or Dropdown labels. CheckboxGroup does not own Switch inputs.

Optional m-bind retains boolean checked semantics. Explicit m-bind-property="value" binds the native submission string. Binding is not a dependency of Switch. ESM imports only markup-ui-core.js; classic scripts load core then markup-ui-switch.global.js. MarkupUISwitch exposes Switch and registerSwitch, not a controller factory. Do not load both formats in one page. No native-input/native-radio chunk, other component constructor, aggregate or metadata runtime is required.

Canonical size/square/status attributes replace archived data-* configuration. The native .m-switch skin and --m-switch-* theme hooks retain light/dark colors, RTL thumb placement and visible dashed loading boundaries. Forced colors and print restore native checkbox painting. There is no animation or transition, including under reduced motion.
