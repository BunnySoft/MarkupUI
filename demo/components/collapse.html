Behavior, accessibility and lifecycle

Keys and state ownership

  • expandedKeys and defaultExpandedKeys accept only readonly string arrays, with nonempty unique keys. No scalar/null aliases, metadata property dispatcher or attribute encoding exists. Collections are copied and returned frozen; item keys must be unique within their direct group.
  • On first initialization, an explicit expandedKeys request wins over defaultExpandedKeys (initially []). After initialization, default writes only change the reset target. Reconnect retains actual native open state; a collection assigned while disconnected overrides it on reconnect.
  • Unknown keys are rejected against connected, rendered items. Requests assigned before connection are validated when anatomy becomes ready. Empty arrays close all items. Invalid writes leave valid expansion unchanged.
  • Accordion rejects multi-key requests. Enabling accordion with several existing open items retains the first open item in DOM order; subsequent native openings keep the latest one. Stale or conflicting default keys make reset throw until the application updates them.
  • expand(key), collapse(key), toggle(key), and reset() require an active group. Disabled prevents user summary activation, not application expansion or native content interaction. There is no group-wide disabled or read-only mode.
  • The group exposes a frozen item list and state disconnected | pending | ready | invalid. Item expanded reads its actual native open state. Setters and actions update native state synchronously; change events follow the browser's asynchronous, possibly coalesced toggle events.

Native structure and input

Author direct m-collapse-item children, each with a required key, exactly one direct m-collapse-header and m-collapse-content, and at most one m-collapse-header-extra. The renderer moves those same region nodes into native details/summary; extras remain outside details. It never clones or replaces your content with HTML. Do not author private details, summary, data-part or native-name anatomy.

Header content must have visible label text and contain only noninteractive native markup. Native headings and decorative icons are allowed. Buttons, links, controls, editable/tabindexed content, nested custom elements, shadow content and interactive roles are rejected inside the header. Put independent actions in header-extra; every extra button needs an explicit button/submit/reset type.

Summary remains the sole accessible owner. Enter, Space, Tab, native focus and form behavior are not synthesized; there is no custom roving focus or arrow-key model. The renderer does not author aria-expanded, tabindex or a redundant button role. Disabled summaries get owned aria-disabled and blocked activation, while their labels remain available. Closing focused content returns focus to a visible summary without stealing focus from unrelated controls. Nested groups remain independent.

Events

m:header-activated follows an uncanceled primary header click and reports key, expanded, public item and originalEvent. m:expanded-changed follows native toggle and reports those fields plus a frozen expandedKeys snapshot; it can also follow initial defaults or programmatic writes. Neither event implies a cancelable transaction or a fixed ordering between header and toggle notifications.

m:error reports an error object when automatic validation fails. All three events bubble, are noncancelable and do not cross shadow boundaries. Filter event.target === group when observing a nested group. To cancel user activation, preventDefault on the original native summary click.

Updates and cleanup

Late children are observed. Missing keys/regions leave the group pending; malformed or duplicate anatomy reports invalid. Fixing markup lets automatic reconciliation recover; refresh() performs immediate validation and also throws on failure. Expansion follows surviving nodes and same-key replacements. Renaming a key retains that item's native state; it does not rewrite stored defaults.

Disconnect removes listeners, observers and queued notifications, restores owned names/ARIA, and retains native open state and authored region identity. Reconnect creates no duplicate summary or extra action. Removed content is not resurrected when regions are replaced. No height animation engine, display directive, virtualization or automatic disposal of closed content is provided.

This renderer targets connected light DOM, not shadow-root or legacy m-accordion-item ownership. Without JavaScript the authored regions remain readable, but native disclosure controls have not been generated.

Styling

Use component color, header/content/extra padding, item-gap and arrow-size/order CSS variables. Scope private data-part/data-state selectors to the owning m-collapse-item and its direct native structure. The default decorative SVG arrow stays centered during rotation, independently of the page font. Only the arrow transitions; reduced-motion and print disable it. High-contrast palettes, separators and focus outlines remain explicit. There is no animated-height dependency.
