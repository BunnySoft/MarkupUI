Behavior, accessibility and lifecycle

Concrete native owners

Author one direct DropdownTrigger containing a labelled native type=button, and one direct DropdownMenu. Each DropdownItem contains exactly one native type=button or href anchor, with an optional direct submenu owned by a button. Menus/groups contain only items, groups, dividers and inert templates. Public item nodes and their native controls are never moved, cloned or replaced.

Every menu/group needs a nonempty label or explicit accessible name via aria-label/aria-labelledby. Group label creates a private visible label; its group owns the accessible name. Menu labels name the menu without adding a visible header. An item label optionally overrides the native action's accessible and typeahead name. Passive native icons/text are allowed; interactive descendants, custom widgets, shadow content and conflicting roles are rejected.

The renderer supplies unique menu IDs and native popovertarget relationships. Do not author private menu/action data markers or competing popover modes. A mismatched explicit native target is an error. The trigger and action own focus; item/group/trigger wrappers never become duplicate controls. Menus use menu roles, native actions use menuitem roles, groups use group and dividers use separator.

Selection and action order

Keys are nonempty strings, unique across a root and all its submenus; independent Dropdown roots may reuse them. Value is a nullable existing leaf key. Writes are silent selection-paint updates, not action activation; disabled leaves may be selected programmatically. Select(key) is a value write followed by close, without clicking or navigating. Accepted native selection reflects the current value attribute, so unrelated property changes never replay a stale initial selection.

Native action listeners/defaults run first. A queued acceptance check honors late defaultPrevented, then updates value/paint, closes the hierarchy, restores safe focus and emits m:selection-requested. This is a noncancelable notification to application code, not a promise that an application command completed. Its source is native (including native .click()); detail also contains key, public item, frozen submenu-key path and originalEvent. Cancel the original click to decline activation/selection.

Modified clicks, downloads and non-self target links retain native browser behavior and are not consumed as selection. No aria-selected/aria-checked, checkbox-menu mode, options-object dispatcher or synthetic application action is added. Group labels are not part of the selected key path.

Keyboard, disabled and positioning policy

ArrowDown/Up on the trigger open at the first/last available action. Scoped arrows, Home/End, bounded case-insensitive prefix typeahead and repeated-character cycling skip disabled items and non-actions. Logical submenu arrows respect RTL; Escape closes the deepest open menu first and restores safe focus. Tab is not prevented: roving state is suspended for native departure and the menu closes afterward. IME and modifier shortcuts remain native. Buttons keep native Enter/Space; anchors receive the missing single Space activation without duplicating Enter or native clicks.

Disabled items block activation. Native buttons use disabled; disabled destination anchors retain identity but temporarily lose href and gain aria-disabled/tabindex=-1, with original values restored on re-enable/disconnect. Native authored disabled buttons remain respected independently of the item flag. Root disabled blocks opening and command clicks and closes the tree, but silent value writes remain allowed.

Root placement retains top/bottom/left/right with optional start/end alignment; top/bottom alignment is logical in RTL, while left/right sides are physical. Submenu sides/arrows adapt to RTL. Flip, viewport clamping and supported CSS-anchor positioning retain their native helper behavior, with a measured fallback. Timing properties are finite milliseconds from 0 through 60000, including fractional values.

Submenu pointer entry waits submenuDelay, departure allows submenuDuration travel grace, and pointer intent does not steal keyboard submenu focus. Root opening is native click or an explicit API request; no automatic hover trigger mode or virtual-coordinate anchor is claimed. SyncPosition() is Web-specific. Invalid or unavailable positioning closes the popup and reports an error when appropriate.

Changes, events and cleanup

Refresh and structural/configuration changes close/revalidate/rebind the tree, retain surviving controls and keyed value, cancel pending work and recover safe focus. A removed or newly branching selected key clears value silently. Missing in-progress child anatomy is pending; invalid anatomy is reported. Explicit refresh also throws on failure. Pre-upgrade property writes are replayed; incomplete roots can accept late children.

Opening is positioned before its first visible frame. Initial paint and animation wait for placement; native autofocus and the menu's keyboard handling retain ownership of focus.

Show is actual root popup state. State also distinguishes disconnected, pending, invalid, disabled and inline fallback. m:open-changed reports actual show with native/api/refresh/disabled reason; native toggles may coalesce, and its delivery has no promised ordering relative to a selection notification. m:error reports validation/positioning failures. All three component events bubble, are noncancelable and do not cross shadow boundaries; filter event.target when composing roots.

Disconnect cancels delayed openings, typeahead, selection tasks, observers, positioning and listeners; it closes popups and restores owned native attributes. Reconnect starts closed with retained value and the same authored nodes. Use owned submenus, not an independently nested Dropdown widget inside menu content. Native light-DOM Popover topology is required: no portalled/shadow-root or legacy m-popover ownership.

When native Popover is unavailable, panels remain inline with original native actions and no simulated popup/menu keyboard roles. Opening returns false; disabled destinations/root clicks are still blocked. Inert native templates are preserved but never instantiated: template, virtualization and arbitrary render adapters are not implemented.

Styling and payload

Size is nullable: absent inherits density/default medium; explicit small/medium/large/huge chooses the retained row metrics. Inverted paint, optional arrow and the existing 100ms Popover opening animation remain available. Reduced motion disables the animation. Passive spans with slot="icon"/"suffix" can carry authored icons, shortcuts or submenu arrows; they do not create additional controls.

Scoped private parts/states replace old public helper anatomy. Existing Popover/Dropdown color, padding, density and selected/disabled tokens retain their precedence, high-contrast and print treatment. Required-file totals count core + Dropdown + composed CSS. Approved ceilings are 13,000 gzip bytes per JavaScript file, 1,850 bytes for composed CSS and 14,000 bytes for JavaScript including shared core.
