Store-bound tasks

Portable item content with stable keys. This example additionally selects state, Input and its native-input dependency, Box, Button, and the optional root facade for named actions.

Task description Remove task Add task Reverse order Remove first task 
const store = MarkupUIState.createStore({
  tasks: [{ id: "a", title: "Report", name: "Quarterly report",
    fieldId: "task-field-a", helpId: "task-help-a" }]
})
const binding = MarkupUIState.bind(document.getElementById("task-workspace"), store)
m.actions.register("task.remove", ({ store, arguments: args }) => {
  store.set("tasks", store.get("tasks").filter(task => task.id !== args.key))
})
const stopActions = m.actions.install(document.getElementById("task-workspace"), binding)
// Collection replacement and edits use this same store.
store.set("tasks", [...store.get("tasks")].reverse())
// On teardown: stopActions(); binding().
// Rebind and reinstall actions together to reuse retained instances.

    API

    Generated from TypeScript accessors and documentation comments at build time, separately from the runtime. Native HTMLElement properties and methods remain available.

    Behavior and accessibility

    Properties and validation

    bordered defaults to true; setting bordered="false" removes the border. size accepts small, medium, or large. clickable and hoverable are presence attributes. showDivider defaults to true and can be disabled with show-divider="false".

    Accessibility and layout

    Lists with direct m-list-item children maintain role="list" on the container and role="listitem" on items. When an explicit items container such as a ul or ol is authored, header and footer stay outside the semantic list. Native ordering, start, and value attributes on ordered lists are fully preserved.

    Portable store-bound items

    One-way data-bind-id and matching data-bind-html-for or data-bind-attr-aria-describedby pair application-supplied IDs. IDs must be unique in the enclosing Web tree and bound references must resolve inside the binding root. Fixed authored IDs in repeated sources and two-way ID/label-target models are rejected. Give each simultaneous placement distinct IDs; the mirrored-source example deliberately has none. Preflight checks the next surviving tree, not atomic intermediate DOM mutations. Label association and native attribute forwarding remain owned by the selected components.

    One direct m-list-template owns the List's item region, with exactly one authored m-list-item root. Header/footer regions remain outside it. Do not mix authored items, another template, or an authored items container into that List. The Web renderer supplies one native ul and stable li instance roots; label names that list. The binder owns placement, while List never independently moves generated items.

    Select state explicitly and call bind(root, store), or use an explicitly selected App with the same store. data-each is the store-owned collection path; data-each-key is required. Nested paths use $item, $parent, and $root; $index and $key are read-only. Update that store to add, remove, or reorder items; appendItem and removeItem reject template mode. items remains a computed snapshot, not a private data collection.

    focus-on-remove explicitly opts into focusing the surviving semantic list when its active row is removed, including removal of the last row. It does not add a Tab stop. An explicit binding focusFallback callback takes precedence. Without either policy, focused removal fails before changing the rendered region. Removing the List itself needs an application fallback outside the removed content. ListTemplate.focus() focuses the list; it does not guess which row control should receive focus.

    After capture, source content is inert and does not participate in forms. HTML parsing or custom-element upgrade can briefly connect authored descendants before capture; this is not a guarantee that source constructors never run. Prefer loading selected families before binding, and do not put side-effectful application initialization in source connection callbacks. Stop retains instances and disconnects binding listeners; same-root rebind reuses them. Moving source chrome or generated roots outside their owner is rejected. Item-scoped action arguments remain unimplemented.

    Web source reuse uses data-template="#id" for an exact, unique native template ID inside the binding root, or data-template="name" for an explicitly supplied BindingOptions.templates Map. A referenced ListTemplate has no inline content, and its definition must contain one ListItem root. The binder copies the definition without consuming it; no document-wide lookup, remote loading or data-to-HTML conversion occurs. Call binding.refresh() after source or Map changes. Changed expanded content replaces affected instances under the same focus policy. Cycles, more than 32 reference hops or 1,000 expanded references per source fail before insertion. Native template definitions are a Web adapter, not portable source definitions.
