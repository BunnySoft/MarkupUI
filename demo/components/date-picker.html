Values, drafts and lifecycle

value is live native state, not the host attribute. defaultValue and the host value attribute configure reset defaults; native dirty flags decide whether a default update also changes the live field. Both programmatic setters are silent and validate the whole incoming model before mutation. Invalid dates, null, Date objects, epoch values, invalid quarters and out-of-domain years throw; they are not sanitized into a successful empty value.

Native user drafts remain editable. An incomplete/invalid quarter or year has value === null, state.badInput === true and the actual native string in state.draft; there is no hidden last-valid host cache. Quarter pattern and year min/max/integer step own native form validity. state.nativeValid reflects native eligibility: readonly/disabled fields may be barred from validation, but their invalid draft still stays null/badInput. state.partial, complete and ordered distinguish partial/reversed ranges; ordering is informational, not a second form validation engine.

Original native input and change events bubble unchanged. Accepted user values emit one deduplicated m:change across input/change; invalid or composing entries expose m:date-picker-draft, not a fabricated valid commit. IME commits settle after composition. Explicit clear() emits a native input/change pair per changed endpoint and one clear notification; readonly/disabled eligibility is all-or-nothing. Programmatic writes, refresh, configuration and native reset do not emit editing events.

picker.value = ["2026-09-30", ""]; // silent partial range, not a reset default
picker.defaultValue = ["2026-09-30", "2026-10-02"];
picker.configure({
  type: "quarter",
  value: "2026-Q4",
  defaultValue: "2026-Q3"
}); // explicit replacement of schema AND live/default values

After initialization, changing type requires configure({ type, value, defaultValue }); incompatible incoming models or native constraints fail before a schema change. Renderer-generated cardinality changes retain the first native field and reuse the second when needed. Authored endpoint cardinality is fixed, so source nodes are never implicitly removed. Scalar hints and settings retain native edits, defaults and focus. Disconnect cancels queued clears/resets and restores only owned mappings; reconnect reuses native nodes and values.

Native Web interoperability and accessibility

The public native array exposes stable editing, validation, focus and form owners. Authored input ids, labels, names, form associations, listeners, ARIA and custom validity are retained. Put external labels on actual native input ids (the custom-element host is not a labelable form control), or supply host aria-label/aria-labelledby. Host name/form/required/readonly/disabled/min/max/step map to the fields; removing a mapping restores authored settings. Native disabled fieldsets and first-legend exceptions remain authoritative. The host gains no extra tab stop or synthetic focus proxy.

Native-only createDatePicker(root, options) remains an explicit Web entry into this same owner: one or two labelled data-date-control inputs inside data-date-picker, with optional initially hidden clear/readout nodes. It retains native date, month, ISO week and local datetime pairs; use explicit { type: "year" } for one number input or { type: "quarter" } for one text input. It does not register other elements, add hidden form fields or install a calendar fallback. Unsupported native date modes fail clearly. Year bounds may be narrowed within 1–9999; quarter uses its fixed native pattern, not text min/max.

format is a retained hint only. It never parses format tokens, converts display text, truncates precision or overrides native locale UI. Native min/max/step and application custom validity stay authoritative. Ordinary field focus/blur and native calendar activation are preserved; no implicit showPicker call or custom calendar is added.

DatePicker itself needs only core, its selected family and CSS. Form, Button and Typography assets on this page are extra example selections. Styling uses external theme tokens and the existing native-control skin, including forced colors and print states.
