Input Number

Empty is not zero. One native number input owns editing, accessible naming, focus, validation and forms. Optional native buttons use browser stepping, not arithmetic or a parser.

Behavior, accessibility and dependencies

InputNumber extends ViewElement and registers only m-input-number. native exposes the original or generated input[type=number]. Name the input with a native label, aria-label or resolved aria-labelledby; do not give the host a role or tabindex or wrap the component in interactive content. Optional [data-number-decrement], [data-number-increment] and [data-number-clear] actions must be named native type="button" controls outside labels. Initially hidden actions become available on enhancement and recover their original hidden/disabled attributes on disconnect; later author changes are retained.

Native absence means value=null; text, defaultValue, name, placeholder, min, max and step are ""; disabled, readOnly and required are false. Effective absent step is 1; malformed constraints keep native interpretation. Size defaults to medium, status to null, round and borderless to false. Host value, min, max, step, name, placeholder, disabled, readonly, required, form, autocomplete, inputmode and naming/description/invalid ARIA attributes forward on adoption and subsequent host changes. Direct native accessors do not reflect back to the host. The value attribute sets the native default, not a forced live value; native dirty state determines the result.

value accepts only a finite number or null. There is no formatter/parser, custom arithmetic, precision promise, rounding, clamping, keyboard interception or selection API. Native typing keeps input/change/invalid targets and flags. Silent assignments and reset emit no input/change. Explicit stepUp()/stepDown() emit input then change only for a real editable numeric change. clear() emits input, change, then noncancelable m:input-number-clear with {previous: {value, text, badInput}}. These action-generated events are untrusted; no m:input or m:change aliases are synthesized. Native input is composed; change/invalid and custom events are not.

Cancel a button click with preventDefault(), including at a later bubbling listener, to prevent its deferred action. Readonly, effective disabledness, hidden/inert state and tracked composition block actions. Value writes during composition throw; native drafts remain untouched. Reset uses the actual form and supports cancellation; disconnect removes listeners, observers and queued actions. Reconnect preserves the owner and native defaults. Stale deferred actions do not run after disconnect, reset or owner replacement. state is a connected snapshot; error and non-bubbling m:input-number-error report invalid anatomy, which can be corrected before refresh().

Only core is required by the runtime: ESM imports markup-ui-core.js; classic loads core then markup-ui-input-number.global.js. MarkupUIInputNumber exports InputNumber and registerInputNumber, not the archived factory. No other constructors, native-input/native-radio engine, aggregate or metadata runtime is loaded. Optional m-bind uses number/null and native input/change; equal-value updates retain bad-input drafts. Binding is not a dependency.

Canonical size/status/round/borderless attributes replace archived data-* styling. The .m-input-number skin and --m-number-* hooks retain native spinners, logical RTL layout, 22/28/34/40px fields, light/dark colors and visible forced-color boundaries. Prefix/suffix content is ordinary authored phrasing, not a second value model. Print hides optional action buttons. There is no animation.
