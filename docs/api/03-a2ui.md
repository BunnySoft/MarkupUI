# Optional A2UI renderer

`@dataengine/markup-ui/a2ui` is a standalone **Web-only, ESM-only** renderer plugin.
It maps a deliberately small A2UI v1.0 catalog to existing MarkupUI components.
It is not full A2UI/Basic Catalog conformance, an agent SDK, or a production-readiness
claim. Core, root and the full catalog do not import or activate it.

The architecture is two optional authoring paths over the same elements:

```text
Application JavaScript -> optional fluent builders -----+
                                                       +-> existing component APIs -> Web DOM
Agent messages -> optional A2UI validation and renderer-+
                   |
                   +-> action callback -> application-owned transport/authorization
```

The shared core, selectable component families, styling/themes, query/state services,
Chart adapter and icon components retain their existing responsibilities. This does
not add jQuery compatibility, a CSS utility framework, an ECharts engine, an icon
catalog, native renderers or a mandatory AI dependency.

## Catalog and supported subset

Negotiate `urn:markup-ui:a2ui:minimal:1`, exported as `A2UI_CATALOG_ID`. The machine-readable
catalog is `@dataengine/markup-ui/a2ui/catalog.json` (`dist/a2ui-catalog.json`), not
demo-generated API metadata. The host can supply it to an agent. The renderer does not
fetch catalog URLs, execute schema code or load components named by remote input.
An omitted surface catalog selects this configured minimal catalog; any other catalog
ID is rejected. Component `@catalogId`, if supplied, must match it.

| Supported | Scope |
| --- | --- |
| `createSurface` | Unique surface ID, optional initial components and object data model. |
| `updateComponents` | Nonempty array of full definitions; replace matching IDs, retain other definitions. |
| `updateDataModel` | Replace root or update an absolute JSON Pointer; `null` deletes. |
| `deleteSurface` | Remove that surface and its listeners. |
| `Text` | Plain-text literal or `{"@path":"/title"}`; body/caption variants; maps to Span. |
| `Row`, `Column` | Static child ID arrays; start/center/end/spaceBetween/spaceAround/spaceEvenly justification and start/center/end/stretch alignment; maps to Box. |
| `Button` | One Text child, default/primary/borderless variants, `action.event`; maps to the native-owner Button. |
| Actions | Name, click-time bound context and optional bound `userMessage`, emitted in a v1.0 envelope. |

Not implemented: other protocol versions/components, `@call`, renderer/agent functions,
templates, checks, editable inputs, two-way binding, Markdown/HTML rendering, weight,
`justify: "stretch"`, accessibility overrides, metadata/extensions or `sendDataModel: true`.
These fields/features are rejected explicitly, not ignored. `sendDataModel: false`
is accepted. Text children give buttons native accessible names; the host should author
meaningful labels and supply the surrounding page landmarks/headings.

## Loading and host API

Load `markup-ui-box.css` and `markup-ui-button.css`, plus optional application theme
styles. Importing `markup-ui-a2ui.js` selects exactly Box, Button and the shared core.
It does not require the fluent builders, state engine, optional root or aggregate.
Keep the generated files together and do not mix with classic or aggregate versions
of these families.

```js
import { A2UI_CATALOG_ID, createA2UIRenderer } from "./dist/markup-ui-a2ui.js"

const renderer = createA2UIRenderer(document.querySelector("#agent-view"), {
  onAction(message) {
    // Validate/authorize business operations here before sending or executing them.
    console.log(message)
  },
})

renderer.receive({
  version: "1.0",
  createSurface: {
    surfaceId: "greeting",
    catalogId: A2UI_CATALOG_ID,
    dataModel: { greeting: "Hello" },
    components: [
      { id: "root", component: "Column", children: ["greeting", "go"] },
      { id: "greeting", component: "Text", text: { "@path": "/greeting" } },
      {
        id: "go", component: "Button", child: "label", variant: "primary",
        action: { event: { name: "continue", context: { greeting: { "@path": "/greeting" } } } },
      },
      { id: "label", component: "Text", text: "Continue" },
    ],
  },
})

renderer.receive({
  version: "1.0",
  updateDataModel: { surfaceId: "greeting", path: "/greeting", value: "Welcome back" },
})

// At teardown:
// renderer.receive({ version: "1.0", deleteSurface: { surfaceId: "greeting" } })
// renderer.dispose()
```

`createA2UIRenderer(container, {onAction})` needs an HTMLElement in the current document.
It appends only its own surface hosts; unrelated container content is untouched.
`receive(parsedMessage)` accepts one already-framed JSON object, not raw strings, SSE
or JSONL. The application owns parsing, connection lifecycle and transport.
`getSurface(id)` returns the host for inspection; do not mutate renderer-owned content.
`dispose()` removes its surfaces/listeners, is idempotent and rejects subsequent messages.
No global `m.use()` installation or mutation of the core API is necessary.

The [local playground](../../demo/ui-api.html) and its [plain JS](../../demo/ui-api.js)
exercise incoming data, outgoing actions and delete/create without a backend.

## Update and lifecycle rules

Each surface has a separate data model and component-ID namespace. IDs are Map keys,
not DOM selectors. Surface IDs cannot be reused during one renderer's lifetime.
Unknown/deleted surfaces are errors. Components may be delivered before their referenced
children, but all reachable definitions must exist before displaying a new tree.
While a tree is incomplete, the host has `aria-busy="true"`; any previous tree remains
visible but cannot emit actions. Stream the missing definitions to resume it.

Candidate messages, graphs and bound text are validated before changing accepted state.
Cycles, repeated child IDs, multiple parents and a non-Text Button child are errors.
Disconnected definitions are retained for subsequent updates; remove unused references
in the same update when moving a child between parents. Deleting a surface clears all
its definitions. Reusing an existing ID with a different component type replaces that
element; unchanged types keep their elements/native owners. Text updates retain their
text nodes. Surviving focus is preserved during structural updates; removing the focused
component moves focus to the surface host. Surface-deletion focus policy belongs to the host.

Omitted, empty or `/` update paths select the root. Nested pointers decode `~0` and `~1`;
relative paths, malformed escapes and unsafe prototype members are rejected. Missing
object parents are created; existing scalars cannot be traversed. Arrays use canonical
zero-based indices, may append at their current length, cannot become sparse, and use
splice semantics for deletion. Root `null` clears to `{}`.

Missing/null text bindings display empty text; other resolved text values must be strings.
Action context values are literals or **top-level** path bindings, resolved at click time;
nested objects/arrays are literal data, not recursive binding expressions. Missing action
bindings resolve to `null`. Callback data is a copy, so host mutation cannot change the
surface model. Outgoing actions contain `version`, `name`, `surfaceId`,
`sourceComponentId`, an ISO timestamp and `context`.

## Errors and trust boundary

Invalid/unsupported messages throw an `A2UI:`-prefixed `TypeError` synchronously and
leave the last accepted surface state unchanged. The host must catch and visibly
report failures, and decide whether/how to send a protocol error through its transport.
This minimal API does not automatically emit protocol error/function envelopes.
Callback exceptions follow ordinary DOM event error reporting; the host owns its
callback's failures.

Only finite JSON data is accepted. Accessors, custom object prototypes, symbols,
undefined values, sparse/cyclic data and `__proto__`/`prototype`/`constructor` keys are
rejected. Limits are 10,000 JSON nodes, depth 32, and 65,536 combined string/key UTF-16
code units per message/snapshotted model; identifiers have at most 128 characters.
Each surface retains at most 256 definitions with at most 32 tree edges on a root-to-leaf
path. A renderer allows 16 live surfaces and 1,024 lifetime surface IDs.
These are explicit limits for this initial small-message profile, not full-protocol limits.

The adapter never interprets text as HTML, evaluates scripts/expressions, fetches URLs
or permits arbitrary element/property names. It preserves native button activation and
uses existing direct component properties. This is not authorization: agent-provided
action names/context are untrusted, and the host must authorize business operations.
