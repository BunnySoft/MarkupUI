# 2. Web renderer

The Web adapter derives `ViewElement` from `HTMLElement` and registers unprefixed classes
under `m-*` names. HTML is authoring syntax and renderer output, not the portable model.

Properties read/write attributes or native properties directly, with explicit defaults and
validation. API documentation is generated by [development tooling](05-meta.md), not read
by the runtime to perform these operations.

## Properties and attributes

| Logical value | Web rule |
| --- | --- |
| Default-false boolean | Presence attribute: absent is false, present is true; `"false"` is still presence. |
| Default-true boolean | Absence uses the contract default; explicit `"false"` disables and `"true"` enables. Empty presence enables. |
| Enum | Validated lowercase token. |
| Number or duration | Validated invariant number; the contract specifies range and units. |
| Resource reference | String/URL mapping where the contract permits it. |
| Object or collection | Property/binding only; no implicit serialization. |

Each property records its encoding; setters and attribute removal must agree with it.
Specify reflection and pre-upgrade property handling. Invalid values need an explicit
policy, not silent coercion. Exact presentation values use CSS/theme tokens.

## Content and DOM choice

| Content | Default mapping |
| --- | --- |
| Primary content | Authored Light DOM. |
| Named static region | Registered `m-*` child element. |
| Repeated/deferred region | Native `template` adapter. |
| Private invariant structure | Native HTML; Shadow DOM when isolation justifies it. |
| Web-only semantic alternative | Explicitly documented native authoring adapter. |

**Light DOM is the composition default, not an absolute requirement.** It simplifies
external CSS, authored content and native form relationships. Its cost is weaker isolation:
page selectors and scripts can reach implementation elements.

Shadow DOM isolates internal structure and styles, but requires deliberate styling APIs,
content projection, event routing and form integration where applicable. Slots can preserve
authored child identity too. Use it for private structure, not to hide public regions.

Neither choice hides HTML from browser DevTools. Light DOM exposes native descendants
directly; Shadow DOM exposes them under a shadow root. Even a closed root is not a
DevTools concealment or security boundary. Inspectability does not make internal tags a
supported public API.

Private markers use `data-part="content"` and `data-state="loading"`, without `m` or the
element name. Scope queries/styles to their owner. Public named regions remain `m-*` elements;
consumers do not author internal markers.

## Events, semantics and lifecycle

Use native activation and events when they represent the contract; use `m:*` for additional
notifications. Each event mapping specifies name, detail, bubbling, cancelability and
shadow-boundary crossing (`composed`). Property assignment may notify state changes but
must not fabricate user intent.

Prefer one native semantic/input owner. Document platform capability differences and
fallbacks. Connect and clean up renderer behavior under the shared lifecycle rules;
reconnection must retain authored nodes and listeners.

Direct Web authoring creates no second serialized element tree. Full document rendering
may retain logical nodes only when explicitly used.

## Styling

Use `m-*` selectors and `--m-*` tokens. Document public styling hooks; expose controlled hooks
for shadow internals when needed. Support readable pre-upgrade/no-JavaScript content where
the element contract requires it.
